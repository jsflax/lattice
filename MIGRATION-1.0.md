# Migrating to Lattice 1.0

One line per breaking change, appended in the same commit that lands it. This
ledger becomes the consumer migration guide and the 1.0.0 CHANGELOG body.

- `Lattice.attach(lattice:)`, `Lattice.attaching(lattice:)`, and the `LatticeBackend.attach` requirement now `throw` (`LatticeError.attachFailed`) instead of terminating the process on schema mismatch / alias collision; new `Lattice.detach(lattice:) throws` (`LatticeError.detachFailed`) drops the attachment's views, DETACHes, and rebuilds the merged schema — wrap call sites in `try` and add `detach` to teardown paths.
- `Configuration.isStoredInMemoryOnly` is replaced by `Configuration.storage`: `.file(URL)` | `.memory(named: String)` (+ `.memory()` for a fresh private database). Migrate `.init(isStoredInMemoryOnly: true)` → `.init(storage: .memory())`; `.init(fileURL:)` spellings keep working. Same-name `.memory(named:)` handles share one same-process database with cross-handle observation; every `.memory()` is isolated. `configuration.fileURL` remains as a computed accessor (setter switches storage to `.file`).
- `LatticeBackend` gained a `detach(_:)` requirement and its `attach(_:)` requirement now throws — custom backend conformers (none known outside this repo) must implement both.
- `.memory(named:)` names are percent-encoded into the backing SQLite URI: names are no longer required to be URI-safe, and two names that differ only by URI-hostile characters ('?', '#', '%', space) are distinct databases.
- The `add` family now `throws`: `Lattice.add(_:)`, `add(_:preservingGlobalId:)`, `add(contentsOf:)`, and the `add(_: any VirtualModel)` overload — wrap call sites in `try`. Backend insert failures (constraint violation, closed handle, I/O) surface as `LatticeError.addFailed(String)` where previously `add(_:)` trapped (`fatalError`) and the VirtualModel overload silently swallowed them (`try?`).
- Re-adding an already-managed object throws `LatticeError.alreadyManaged` (new case) instead of an unconditional message-less `fatalError()`; `add(contentsOf:)` now pre-checks every element and throws `alreadyManaged` before anything is inserted (previously unchecked passthrough to the bulk path).
- `LatticeBackend.addPreservingGlobalId` and `LatticeBackend.addBulk` requirements now `throws` (contract stability; the Cxx conformances never throw today because the bridge exposes no failure signal on those paths) — custom backend conformers (none known outside this repo) must adopt the throwing signatures.
- `EmbeddedModel` reads are now tolerant: `getField` returns the type's default value (with an error log) on empty or undecodable stored JSON instead of trapping; JSON *encode* failures on the write path still trap, now with a message naming the type.
- `Configuration.init` no longer traps when no documents directory exists (headless Linux/daemon contexts): the default database location falls back to the current working directory with a warning log.
- `syncProgressStream` no longer crashes the process if its background query Lattice fails to open (cross-process path) — it logs and finishes the stream.
- `Lattice.transaction { }` now ROLLS BACK on throw and rethrows (previously a throw left the write transaction open, wedging the connection until the busy timeout killed the process). New `rollbackTransaction()` alongside begin/commit; `LatticeBackend` gains a `rollback()` requirement.
- (item A, Commit 1) Live `Results` `count`/`subscript` reads are **generation-cached** (one logical epoch per lattice, resolved at most once per main-thread runloop tick) instead of statement-fresh. Same-handle read-your-writes is preserved exactly (`add`/`delete`/`transaction`/managed-property setters advance the epoch synchronously before returning); a *cross-handle* same-process writer's commit becomes visible on this handle after the existing observer delivery (≤ one scheduler hop) until the synchronous core invalidation hook lands (spec §2.3, Commits 3–5). `Results.refresh()` forces an advance.
- (item A, Commit 1) Out-of-bounds / cross-generation `Results`/`Slice` subscripts **serve the tolerant ladder** (current fill → retained previous page → lifeboat → an unmanaged default-valued placeholder instance) **instead of trapping** (previously `fatalError("Index out of bounds")`). New `element(at:)` returns `nil` instead of a fabricated element; `@Relation` access on a not-yet-inserted instance returns empty results instead of trapping.
- (item A, Commit 1) Baseline memory grows by the bounded per-shape page cache (`ResultsTuning`: `pageSize` × `maxCachedPages` hydrated rows per query shape, ≤ `maxCachedShapes` shapes per lattice, LRU-evicted; tune via `Configuration.resultsTuning`).
- (item A, Commit 5) Live `Results` reads are now **generation-consistent** (spec §6 line 1): on file (WAL) databases every count/page fill/`snapshot()` for one render batch executes at ONE pinned MVCC snapshot (a pooled read-only "keeper" connection holding an open read transaction); on memory-family databases (`.memory(named:)` / `.memory()`) the generation is a per-query-shape materialized-id vector captured under the per-store write gate. Cross-handle same-process commits (second handles, sync-applied chunks) now bump the epoch **synchronously on the writer's thread before the write call returns** (the §2.3 core invalidation hook replaces the interim scheduler-hopped observer signal); a cross-THREAD commit becomes visible at the next render-batch boundary (one frame is single-generation by construction).
- (item A, Commit 5) Memory-family databases: a row deleted concurrently with a render can hydrate as an **invalidated (default-valued) placeholder** for ≤ 1 frame (spec §6 line 6); iteration skips such rows. `for x in results` on file databases now iterates at a captured generation and, if that generation is force-retired mid-walk (TTL/threshold/lifecycle), transparently re-pins and resumes by keyset anchor — rows are still visited at most once, in order.
- (item A, Commit 5) File databases accept a `-wal` sawtooth up to `ResultsTuning.walKeeperEvictionThresholdBytes` (default 16 MB; forwarded to the core WAL-threshold keeper eviction, spec §3.4) plus up to `keeperPoolSize` (3) extra read-only connections per instance; idle generations self-retire after `ResultsTuning.generationTTLSeconds` (default 30 s) via a coordinator-owned maintenance timer that exists for EVERY configuration, including non-sync lattices (spec §3.2, §6 line 5).
- (item A, Commit 5) **Backgrounding retires all read generations** (transparent — facades re-pin lazily on the next access after foregrounding; epoch-keyed caches survive). Where UIKit is available this rides `UIApplication.willResignActiveNotification` / `protectedDataWillBecomeUnavailableNotification` automatically. **App extensions and non-UIKit hosts on shared app-group containers MUST call the new `Lattice.retireAllGenerations()` before suspension** (a suspended process holding WAL read-marks in a shared container is killed with `0xdead10cc`); SwiftUI hosts where those notifications do not fire should call it from a `ScenePhase` hook (spec §3.6, §6 line 8).
- (item A, Commit 5) `LatticeBackend` gains the synchronous-invalidation + read-generation requirements (`addInvalidationHook`/`removeInvalidationHook`, `acquire`/`retain`/`release`/`retireAllReadGenerations`, `readGenerationsOutstanding`/`localReadGenerationsOutstanding`, `runReadPoolMaintenance`, the pool tunables, `objectsAt`/`countAt`/`objectsWithinBBoxAt`/`queryIDs`/`dataVersion`/`lastGenerationReadStale`) — custom backend conformers (none known outside this repo) must implement them.
- (item A) Live results with NO explicit sort now carry an implicit `ORDER BY id ASC` (keyset pagination requires a total order) — result order for unsorted queries is now deterministic oldest-first instead of SQLite scan order.
- (item A) Cross-process freshness is a bounded-staleness contract: a foreign process's commit becomes visible within `ResultsTuning.crossProcessBeltIntervalMs` (default 500 ms, `PRAGMA data_version` belt) or on any same-process write/notification, whichever is first — not instantaneously. Same-process writes remain read-your-writes exact.
- `Lattice.changeStream` is now `AsyncThrowingStream<[AnySendableReference<AuditLog>], any Error>` (was `AsyncStream`) — iterate with `for try await`. The blocking query-Lattice open hops OFF the caller's task (creating/iterating the stream no longer wedges the caller with non-suspending core work, so `.timeLimit`/cancellation can fire), while the AuditLog observer still registers synchronously at stream creation — the "stream created ⇒ subsequent commits are captured" contract is preserved (raw batches buffer until the open completes, then flush in order). A failed background open surfaces as a thrown error at the first iteration instead of trapping the process (was `try!`); cancellation promptly ends iteration and removes the observer.
- Dead-symbol sweep (G6): the public no-op `enum Deprecated` and the duplicate `typealias CxxManagedLatticeObject` (use `CxxManagedModel` — both aliased `lattice.ManagedModel`) are removed; the long-commented-out `LatticeExampleServer` executable target, its `Sources/LatticeExampleServer/` tree, and the orphaned `fluent`/`fluent-sqlite-driver` (+ commented `jwt`) package dependencies are gone from `Package.swift`. Zero uses of any removed symbol found in Engram, Orbital, Nest, or engram-server.
- `Lattice.onSyncProgress(_:)` is removed (G7) — `syncProgressStream` is the canonical progress API (`for await progress in lattice.syncProgressStream`), with `syncProgressPublisher` as the Combine adapter (now stream-backed; cancelling the subscription clears the underlying handler, where the old callback leaked for the backend's lifetime). The stream's non-sync-agent branch now rides the xproc idle hint (the removed callback's passive path) instead of opening a query Lattice + AuditLog observer — one fewer failure mode, same yields. Known consumer sites to migrate (Engram; do a mechanical callback→`for await` conversion): Sources/EngramDaemon/EngramDaemon.swift:168,182; Sources/EngramVisualizer/Account/SyncManager.swift:138,144; Tests/EngramTests/IPCRelaySyncTests.swift:936.
- `DynamicResults.sorted(by:ascending:)` is renamed `sortedBy(_:ascending:)` (G7) — one sort spelling across the API surface (the typed `Results` family already uses `sortedBy`). No external callers found (grepped Engram, Orbital, Nest, engram-server; the lattice-mcp provider updated in-repo).
- `__globalId` is removed (G1): the deprecated `Model.__globalId` protocol requirement is gone and the `@Model` macro no longer emits it — `globalId` is now the macro-emitted stored `@Property` itself (public get, `internal(set)` inside the model's own module) instead of a computed mirror of a public-settable `__globalId`. Migration is a mechanical rename: `.__globalId` → `.globalId` (reads, `!`-unwraps, and query keypaths — `\.globalId` now resolves to the stored column directly). Seeding a specific globalId on insert goes through the existing channel `add(_:preservingGlobalId:)`; no consumer writes to `__globalId` exist. Also removed: the dead macro-emitted `__GlobalIdName`/`__GlobalIdKey` per-model helper structs and their now-orphaned public `StaticString`/`StaticInt32` protocols (Lattice's `StaticString` shadowed `Swift.StaticString` in any file importing Lattice; zero conformances anywhere). Consumer hits to rename (all reads): Engram 142 across 22 files (EngramKit MemoryTools*/SyncService/Migrations, EngramVisualizer Graph/Galaxy, EngramPreview, tests); engram-server Tests/EngramServerTests/SyncE2ETests.swift:138. Zero in Orbital and Nest.
- `List` no longer conforms to `Codable` (G2, DROPPED not fixed): the conditional `List: Codable where Element: Codable` conformance is removed outright. Its `init(from:)` was an unconditional `fatalError()` stub — decoding any model graph containing a `List` terminated the process — and the working encode half had no callers: `@Detached` mirrors lists as plain `[Detached]` arrays with their own synthesized Codable, the `@Codable` macro has zero uses in any consumer, and no consumer JSON-encodes a managed model graph. Serialize via `@Detached`; a future `@Codable` model with a `List` property is now a compile-time error (mark it `@CodableIgnored` or detach first). Zero consumer hits (grepped Engram, Orbital, Nest, engram-server for `List` Codable use and `JSONEncoder`/`JSONDecoder` over model graphs).
- `MigrationContext.enumerateObjects(table:callback:)` is reimplemented (G3): the callback signature changes from the never-functional `(any Model, any Model) -> Void` stub (the body was commented out — it compiled but did nothing) to `(Int64, [String: ColumnValue]) -> Void`, delivering each row's `id` plus the full old row as column-name → new public `ColumnValue` (`.null` / `.int64` / `.real` / `.text` / `.blob(Data)` — one case per SQLite storage class, mirroring the core `column_value_t` variant, with `int64Value`/`doubleValue`/`stringValue`/`dataValue`/`isNull` accessors; `doubleValue` widens `.int64` per SQLite numeric affinity). New `MigrationContext.setValue(table:rowId:column:value: ColumnValue)` stages per-row writes (bridge `setRowValue`). This `(rowId, [String: ColumnValue])` shape is frozen as the 1.1 unified-open C ABI alignment target (latticecore docs/design-unified-open.md §3). Reachability note: no public open invokes a `MigrationContext` block in 1.0 — the versioned `[Int: Migration]` dictionary remains the wired migration path (the bridge factory that accepts a Swift block routes through core `configuration.migration_block`, which only fires on C++ `schema_registry` changes — always empty in Swift processes); the block-based open lands with the 1.1 unified-open ABI. Zero consumer callers of `enumerateObjects` (grepped Engram, Orbital, Nest, engram-server). BLOB contract: the Swift versioned row-transform path migrates BLOB-bearing tables preserving blobs byte-for-byte (now test-pinned); the rc.1 explicit BLOB refusal applies to the C ABI's `lattice_db_create_with_migration` only.
