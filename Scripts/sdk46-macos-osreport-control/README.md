This packet proves only whether hosted Swift 6.3.3/macOS can retain a useful OS report for the tiny known SIGSEGV control. It contains no reachable SDK/Core checkout, package resolution, SDK compilation, test-suite invocation, network action, debugger, permission change, or fallback. Diagnostic source002 and failed run35387156738 stay unchanged. The existing full SDK diagnostic is not yet switched to this mechanism.

`control_probe.py` copies the exact existing `CrashControl.swift`, records the exact `swift --version`, compiles with the original `-Onone -g -module-name SDK46CrashControl` arguments, and launches the binary directly through the unchanged copied supervisor. Native caps are 30 seconds for version discovery, 60 for compile and 10 for execution. The actual signal receipt must show `-11`, clean leader/group cleanup, no intervention, timeout or evidence error. A raw command receipt still says failure for that signal; only the explicitly expected-control classifier can accept it. The refused `SWIFT_BACKTRACE` setting remains recorded; an OS report, rather than runtime stderr, must supply the frame.

The control-only overall ceiling is 240 seconds with 30 seconds reserved for finalization. This contains the native caps, a complete newly approved 60-second report-arrival window, and bounded source/receipt overhead. Before entering that window, the runner requires all 60 seconds remaining in its work budget. The original supervisor retains the 12 GiB free-space floor, 30 GiB packet ceiling, 512 MiB log limit, signal handling and owned-process cleanup. No original SDK test deadline is changed.

`control_reports.py` is a narrow copy of source002's hardened collector. It accepts an explicit regular executable directly below this owned run's `control` directory, uses that basename as its filename prefix and that exact path as its content marker, and performs one scan of at most 60 seconds. It reads the same user/system DiagnosticReports directories. Regular-file/no-follow/stable-identity checks, 8 MiB per file, aggregate 8 files/16 MiB, 64 eligible read attempts, 4,096 entries per directory pass, bounded metadata, reserved custody before writing, stop-on-output-failure and final rehash are retained. Only reports containing the exact owned path are copied. The strict parser, not filename or content substring matching, establishes admission. The limits are aggregate for this control-only job; a later combined control+SDK collector must not reset them between phases.

The parser currently supports a modern Apple `.ips` JSON body, optionally preceded by one metadata JSON object. It requires exact executable path/PID, capture time inside the launch-to-scan window, consistent optional process-launch time, SIGSEGV with EXC_BAD_ACCESS/EXC_CRASH, one explicitly triggered thread matching `faultingThread`, and a symbolized `latticeSDK46DiagnosticCrashControl()` frame on that thread. The frame's image index must point to the exact control path and include a UUID. Whole-second timestamp serialization permits only floor/ceil of the measured endpoints. A source string, another thread's frame, a different image, address-only frames or malformed/ambiguous data reject.

This schema and function rendering remain **prospective** until actual hosted output is retained. Legacy `.crash` files are copied within the same limits but deliberately cannot qualify this JSON parser. If the OS omits the symbol or uses an unhandled format, the job fails with raw reports and bounded rejection reasons retained. No `atos`, `dwarfdump`, dSYM generation, heuristic address attribution or extra symbolication step is presumed. A separately reviewed change can use the actual report and binary identity if needed; there is no automatic retry.

Acceptance is authoritative only in final `RESULT.json` with `success=true`, `controlCaptureAccepted=true`, no errors/signals and final source/binary/report hashes intact. A preliminary `CONTROL-ADMISSION.json` alone never admits SDK work. All SDK/full-suite/release/cause flags remain false even on a successful control. Missing reports, unsupported symbolication, failed final custody or final result write force capture acceptance false.

Root may run, remotely and only after review:

```text
python3 -B control_probe.py --root <fresh absolute path under ~/localdev> --source-seal-sha256 <reviewed SOURCE-SEAL.json SHA256>
```

No native process was launched during preparation. `test_control.py` passed 24 synthetic parser/custody tests in 0.024 seconds using only Python and tiny owned files. These checks do not prove hosted report generation. After this mechanism is actually proven, integrating it into the SDK diagnostic must preserve exact graph identity, original full-suite selection/default concurrency, 1800-second cap and all assertions; this packet does not perform that integration.
