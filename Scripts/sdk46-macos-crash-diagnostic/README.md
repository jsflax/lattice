# SDK46 macOS crash diagnostic

This is a prepared diagnostic, not a product correction or a claim that the original signal 11 has been explained. Root owns source review, workflow installation and remote admission. No local SDK build is requested.

The exact SDK46 / Core836 graph and hosted Swift 6.3.3 are fixed in config.json. The qualification workflow commit is separately recorded; it is never substituted for the SDK commit. The default Debug build, 34 dependency identities and 33 complete non-Core pin records remain authenticated. Core/bridge actual -O0 input objects, test bundle and source hashes are anchored before either test arm and rechecked afterward. No compiled artifact is reused from the historical failed run.

Before downloading SDK/Core or resolving/building that graph, the runner compiles a tiny -Onone/-g Swift control and runs it with `SWIFT_BACKTRACE=enable=yes,interactive=no,output-to=stderr`. Acceptance requires actual SIGSEGV exit, a stack frame containing the non-inlined control function and complete process-group cleanup without guard signals. That environment syntax and stack rendering are prospective on Swift 6.3.3: if the control fails, the packet stops before the SDK build. No debugger fallback or retry is automatic. Core dumps are disabled.

The first SDK arm runs exactly three ProjectionMemoryConsumerExecutorTests and the paused-memory test, checked through ordinary SwiftPM discovery and actual Swift Testing XML/results. Its assertions and five-second operation deadline are unchanged. The second arm uses the original full `swift test --skip-build` selection and default concurrency with the same 1800-second command cap. The focused arm is not a substitute for the full suite. A clean failed assertion/process exit can be followed by the full arm; a timeout, interrupted command or uncertain group cleanup stops admission. Each arm runs once.

A copied reviewed supervisor keeps the original 12 GiB free-space floor, 30 GiB packet ceiling, 512 MiB command-log ceiling, 210-minute whole-run limit, 10-minute finalization reserve and owned-group cleanup. Build remains -j2 with a 5400-second limit. The tiny control has 60 seconds for compilation and 10 seconds for execution. The four-case arm has a bounded 1800-second outer cap; it does not modify any test deadline. No native command has been run while preparing these inputs.

Report collection is one shared session, up to three 3-second scans: after a failed focused arm, after a failed full arm, and after final source/graph authentication when an arm failed. It accepts only regular, stable report files naming the exact owned test bundle. Aggregate limits remain 8 files / 16 MiB, 8 MiB per file, 64 eligible read attempts, bounded directory inventory and error text. A retry of an unstable report consumes another read attempt. Duplicate contents are not recopied. The full byte/file charge is reserved before writing; an output error retains that charge and partial-file status and halts collection. Scalar scan times, directory-presence counts, filename/time eligibility and incomplete reads distinguish absent/late/filtered evidence without assigning the crash to a test. Final completed-file hashes are rechecked. Partial or final receipt failures cannot produce acceptance.

The original failure and Linux pass remain immutable. A successful diagnostic suite is only a result for this exact run; it does not establish a crash fix or release qualification. Missing capture, failed tests or failed final custody remain failures. Runtime, platform and backtrace-control proof remain pending remote execution.
